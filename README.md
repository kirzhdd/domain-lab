# domain-lab
my study windows domain + trust

## theory
домен - группа компьютеров\
сервер - компьютер, выполняющий определённую роль в домене\

дерево доменов - несколько доменов, разделяющих общее пространство имён\
лес доменов - территория(*), объединяющая несколько деревьев доменов.\
территория = общая схема + кофигурация + глобальный каталог

FQDN(fully qualified domain name) - полностью определённое имя домена

FQDN для домена, как зоны = realm в smb.conf, используется как dns-суффикс\
FQDN для компьютера (!) = <Имя компьютера>.<Имя домена>

и то, и то - полное доменное имя

NetBIOS - уникальное короткое имя

NetBIOS домена - короткое имя домена ```в smb.conf задаётся в workgroup```\
NetBIOS для компьютера - имя компьютера ```в smb.conf задаётся в netbios name```

------------------------------------------------------
что нужно для подготовки сервера перед развертыванием домена:

статическая ip-адресация - мы вручную прописываем постоянный ip устройству, вместо того
чтобы его назначали динамически. это нужно для того, чтобы все знали точный адрес днс-сервера,
а роль днс сервера играет контроллер домена. так для всех остальных компьютеров в домене
днс-сервер это контроллер, а для самого контроллера - это он сам

днс-пересылка - это когда сервер не может сам ответить на запрос и пересылает его другому серверу \
есть два типа пересылок:
1. обычная пересылка (forwarders) - всё, что не обрабатывается переслать на другой днс-сервер
2. условная пересылка (conditional forwarders) - только запросы для конкретных доменов летят на 
конкретный днс-сервер


------------------------------------------------------
виды доверия:\
external - связывает два конкретных домена из разных лесов\
forest - связывает два леса

у доверия есть параметр проверки подлинности\
full authentification (полная проверка подлинности) - означает, что как только пользователь из другого леса прошёл
аутентификацию в моем лесу, то он попадает в "Authenticated Users", которым доступно всё в моем лесу\
selective authentification (выборочная проверка) - идёт разграничение, что в каком лесу кому доступно

SID

SID (Security Identifier) - уникальный неизменяемый индентификатор безопасности, как серийный номер, который нельзя изменить.
SID пользователя = SID самого домена + RID (Relative ID) пользователя.

SID History - механизм (атрибут), который позволяет пользователю "взять с собой" старый SID при миграции из одного домена в другой\
SID Filtering - механизм безопасности на уровне доверия, который "отсекает всё лишнее" - вырезать из входящих токенов SID'ы, которые не принадлежат доверенному домену

(!) [архитектурное ограничение Samba](https://www.altlinux.org/ActiveDirectory/Trusts#%D0%94%D0%BE%D0%B2%D0%B5%D1%80%D0%B8%D1%82%D0%B5%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5_%D0%BE%D1%82%D0%BD%D0%BE%D1%88%D0%B5%D0%BD%D0%B8%D1%8F_%D0%BC%D0%B5%D0%B6%D0%B4%D1%83_Samba_DC_%D0%B8_Windows_Server_%D1%81_Active_Directory:~:text=%D0%9D%D0%B5%20%D0%BF%D1%80%D0%B8%D0%BC%D0%B5%D0%BD%D1%8F%D1%8E%D1%82%D1%81%D1%8F%20%D0%BF%D1%80%D0%B0%D0%B2%D0%B8%D0%BB%D0%B0%20%D1%84%D0%B8%D0%BB%D1%8C%D1%82%D1%80%D0%B0%D1%86%D0%B8%D0%B8%20SID)\
